# Floria Architecture

Designed for a small immersive-marketing codebase: one public route (`/`),
two internal dev-tooling routes, and a component library organised by intent.

## 1. Routing layer (`app/`)

Next.js App Router owns routing and nothing else. Every route file is thin:

- `app/layout.tsx` — fonts, viewport, metadata (values from `@/config/site`).
- `app/page.tsx` — renders `<HomePage />` from `@/features/home`. No logic here.
- `app/globals.css` — bridge file re-exporting `src/styles/globals.css`
  (Next requires the stylesheet to be importable from `app/`).
- `app/extract/page.tsx` + `app/api/extract-frame/route.ts` — **internal tooling**
  used to generate scroll-sequence JPEG frames. Not part of the public UX.

## 2. Feature layer (`src/features/`)

One folder per user-facing capability. Today there is one feature:

- `src/features/home/HomePage.tsx` — composition root for `/`.
  Owns hero spotlight interaction state (mouse/touch refs, rAF loop) and
  composes `HeroSection` + `StorytellingSection` + `FloriaDiscoverySection`
  + `FloriaFooter` + `LuxuryPreloader`.

Future features (e.g. `features/archive/`) follow the same pattern:
feature owns state, sections stay presentational.

## 3. Component layer (`src/components/`)

Organised by role, each with an `index.ts` barrel:

| Folder | Role |
|---|---|
| `sections/Hero` | Full-viewport spotlight hero (presentational) |
| `sections/Storytelling` | Scroll-driven frame cinema |
| `sections/Discovery` | Interactive specimen archive |
| `layout/Footer` | Art-book colophon footer |
| `ui/Preloader` | Fullscreen loading overlay |
| `viewer` | 3D viewer placeholder (currently null render) |

Import rule: `import { FloriaFooter } from "@/components"` or the
section barrel — never `../../components/...`.

## 4. Shared kernel (`src/config`, `src/lib`, `src/hooks`, `src/types`)

- `config/site.ts` — brand name, tagline, links, metadata. Single source of truth.
- `lib/utils.ts` — `cn()` class joiner.
- `lib/frames.ts` — `FRAME_SEQUENCE` constants + `getFrameSrc()` resolver.
- `hooks/useIsMobile.ts` — touch/mobile heuristic shared by hero + sections.
- `hooks/useLockedScroll.ts` — scroll-lock for fullscreen overlays.
- `types/floria.ts` — `Specimen`, `BloomItem`, `FrameSequenceConfig`.

## 5. Styling (`src/styles/`)

`src/styles/globals.css` is the design-system source of truth
(Tailwind v4 theme tokens, scrollbar, keyframes). `app/globals.css` only re-exports it.

## 6. Static assets (`public/`)

- Hero: `bg_image_1.jpg`, `bg_image_2.jpg`, `story_landscape.jpg`.
- Discovery: `discovery/specimen_*.jpg`, `discovery/bloms/*`, `discovery/videos/*`.
- Frame cinema: `frames-part1/*`, `ezgif-*-jpg/*` (generated by the extract tooling).

## Conventions

1. `app/` files under ~30 lines. Anything bigger belongs in `src/`.
2. No magic strings for brand/links — use `@/config/site`.
3. No duplicated frame-math — use `@/lib/frames`.
4. Client components declare `"use client"` at the top.
5. Absolute imports via `@/*` (`src` first, then root fallback).
